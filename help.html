🧭 出差行程規劃工具 — 使用說明書

單一自包含 HTML・離線可用・零安裝・繁體中文 / 日本語 / English

本工具是一個 單一 HTML 檔(index.html)。雙擊即可用任何瀏覽器離線開啟,不需安裝、不需連網,也不會把任何內容上傳到外部——你輸入的所有資料都只留在你自己的電腦。

1. 簡介與核心特色

本工具用於規劃出差 / 旅行的多日行程,一份行程可完整記錄:每日行程動線、交通(可多段轉乘)、餐食、住宿、附件(車票 / 訂房單),以及依幣別彙總的花費統計,另附攜帶清單與購物清單。完成後可輸出成 PDF 或 Excel。

設計理念

  • 單檔自包含、離線:整套功能包在一個 HTML 檔內,雙擊即用,無網路也能運作。唯一內含的第三方元件是用於把 PDF 附件轉圖列印的 PDF.js(已內嵌於本檔,純本機運算、不會連網)。
  • 資料只留本機:不上傳、不外送;編輯過程自動暫存於瀏覽器。
  • 三語介面:繁中 / 日文 / English,可隨時切換;你輸入的內容不會被翻譯。

三種檔案的角色(重要)

格式角色能否再編輯
JSON唯一的儲存 / 讀取格式,含全部內容與內嵌附件✔ 可完整還原
PDF交付 / 列印用輸出(走瀏覽器列印)✘ 僅輸出
Excel表格整理用輸出✘ 僅輸出
一句話原則:要「之後還能改」就存 JSON;要「給別人 / 列印 / 歸檔」就輸出 PDF 或 Excel。

2. 開始使用

2.1 開啟工具

雙擊 index.html,以預設瀏覽器開啟(建議 Chrome / Edge)。首次為繁體中文,可於設定更改。

2.2 首頁

首頁標題「行程規劃」,提供三個入口:

項目說明
新建行程從頭建立一份新行程(第 3 章)。
讀取行程開啟先前另存的 .json 續編(第 10 章)。
↻ 繼續上次行程有上次未關閉的行程時才出現;載回上次行程繼續編輯(第 10 章)。
⚙️ 設定佈景 / 幣別 / 語言,頂端常駐(第 11 章)。
提示:語言 / 佈景 / 幣別為「全域偏好」,會被記住並由新行程繼承。

3. 建立新行程

首頁點「新建行程」,依序填寫:

  1. 出發日期:以「年 / 月 / 日」三下拉選取。之後每天日期依「排第幾天」自動推算。
  2. 總天數:1–60;日後仍可於「日程設定」增減(第 8 章)。
  3. 行程名稱:例「中部供應商稽核」,會與出發日組成標題 / 檔名。
  4. 確認預覽的「產生的行程標題」(yyyymmdd行程名稱)後按 建立行程表。

4. 編輯器導覽

4.1 四大分頁

分頁用途
行程逐日編輯行程、交通、餐食、住宿、附件(第 5 章)。
花費總覽依幣別彙總花費(第 6 章)。
攜帶清單 / 購物清單物品與採買清單(第 7 章)。

4.2 標題

上方標題可直接點擊修改;不改則用「yyyymmdd行程名稱+天數後綴」預設。用於 PDF / Excel 內文與檔名。

4.3 顯示模式

「行程」與「花費總覽」各有 🗂️ 逐日顯示 / 📄 一頁顯示 切換,僅影響檢視,不影響輸出。

4.4 右下角浮動按鈕

編輯行程時,畫面右下角常駐兩顆浮動按鈕(由下而上堆疊):

按鈕功能
🗓️ 日程設定調整出發日期、總天數、各天順序(見第 8 章)。
📋 行程總覽開啟完整預覽,並可匯出 PDF / Excel(見第 9 章)。
拖曳排序:兩處可用滑鼠拖曳(按住 ⠿ 握把)——同一天內的行程項目(見 5.3)、日程設定面板內的各天(見 8.3);兩者也都能用 ▲ ▼ 按鈕。

5. 行程編輯

每一天由四區塊組成:行程、餐食、住宿飯店、附件。

5.1 行程項目與目的地

按 ＋ 新增行程。欄位:

欄位說明
目的地主標題(可留空);留空時自動改用「抵達地」。
出發地 / 出發時間起點與時間(24 小時制,點欄位可捲動挑選)。
抵達地 / 抵達時間終點與時間。
移動區間交通方式(見 5.2)。
備註補充說明。
範例
目的地:台中高鐵站　·　高雄 06:55 → 台中高鐵 10:55
🗺️ 地圖(本檔為「連網版」專屬):「行程 N」右側的 🗺️ 可在卡片內展開 Google 地圖,自動顯示「出發地 → 抵達地」的路線(抵達地留空時改用「目的地」;只填一端則單點顯示該地點)。地圖下方有 「在 Google 地圖開啟 ↗」 可改用新分頁看完整地圖。
· 每天一張完整路線圖:每天標題列右側有 🗺️ 本日路線,會把當天所有行程依序串成一條多點路線。若下一筆行程的出發地就是上一筆的抵達地,該地點只算一個點(A→B、B→C 得到 A→B→C);若出發地不同,則兩個點都保留(A→B、B'→C 得到 A→B→B'→C)。
· 本日路線的兩個限制:大眾運輸不支援多點路線(有中途點時會自動改以開車模式顯示,要查大眾運輸請用單筆行程的地圖);中途點上限 9 個,超過時會省略中間的點並在地圖下方明確告知省略了幾個(起點與終點一定保留)。
· 地圖上方有四個交通模式:🚗 開車 / 🚆 大眾運輸 / 🚶 步行 / 🚲 自行車,點選即以該模式重新載入,並記住您的選擇(下一筆行程展開時沿用)。
· 「銀座線 或 JR」這類多條建議路線,請點「在 Google 地圖開啟 ↗」——它會帶著您目前選的模式開啟,Google 地圖網頁才會列出各路線的時間與轉乘。卡片內的小地圖只畫一條路線,這是內嵌地圖的限制。
· 同時只會展開一個地圖(展開新的會自動收合舊的),再按一次 🗺️ 即收合。
· 修改地點欄位後,收合再展開即以新地點重新載入。
· 地圖需要網路(展開的那一刻才向 Google 載入);地圖不會出現在 PDF / Excel 輸出中。若您所在環境禁止連外,請改用 offline/ 的離線版(無此功能,亦不含任何連網程式碼)。

5.2 移動區間與移動手段

「移動區間」內可放多個「移動手段」描述轉乘。每段可填:手段 / 交通工具名稱、出發地 → 抵達地、出發 / 抵達時間、移動時間、花費。

轉乘範例
手段 1:高鐵(高雄→台中)08:00–09:00　·　手段 2:計程車(台中站→飯店)09:10–09:30
移動時間:當某段的起訖時間不確定時,可只填「移動時間」(分鐘,最多 3 位數,不參與時間邏輯檢查)。輸出時:兩個起訖時間都有 → 依起訖時間;缺一個或都沒填 → 在路線後顯示「移動xx分」底色徽章;Excel 另有「移動時間」欄顯示「xx分」。

5.3 調整行程順序

  • ▲ / ▼ 按鈕:與相鄰行程對調(手機 / 桌機皆可)。
  • 拖曳(桌機):按住標題列 ⠿ 握把拖動;拖到視窗邊緣會自動捲動,限同一天內。

5.4 餐食

按 ＋ 新增餐食。欄位:名稱、地址、電話、傳真、Email、網站、用餐時間、是否已訂位 / 訂位時間、預估花費。

5.5 住宿飯店

按 ＋ 新增住宿飯店。欄位:名稱、地址、電話、傳真、Email、網站、入住 / 退房、住宿費用。

5.6 附件

按 ＋ 匯入附件 匯入圖片或 PDF;附件內嵌於行程檔,JSON 會一併攜帶。

輸出呈現:圖片在 PDF 每張一頁、Excel 內嵌;PDF 附件會逐頁轉成圖片,接在圖片附件之後印出(每頁一頁),因此行程與各式憑證可一次列印完成。
・轉換於按 📄 匯出 PDF 或 📋 行程總覽 時進行;附件多時需稍等,畫面會顯示進度提示。
・單一 PDF 附件最多轉 30 頁;超出的頁數會在該附件最後一頁明確標示省略幾頁,不會默默截斷。
・少數 PDF(例如加密檔)可能無法轉換,這些會退回末頁清單呈現;原檔仍可在工具內開啟。

5.7 時間邏輯提醒

時間不合理時以紅字即時提醒(行程間出發遞增、抵達不早於出發、移動段落在範圍內)。只在編輯畫面顯示,不進輸出;留空自動略過。

6. 花費與花費總覽

交通、餐食、住宿、購物都可記花費,每筆為「金額 + 幣別」(共 18 種)。

・留空不計入統計。
・不同幣別分別加總,不做匯率換算。

「花費總覽」分頁依幣別分組列出交通 / 餐食 / 住宿與小計,可切 🗂️ 逐日 / 📄 一頁;0 值列與整組為 0 的幣別自動隱藏。

7. 攜帶與購物清單

兩者操作相同,各可建多份清單(子頁籤切換):

清單項目可填
攜帶清單名稱、數量、小圖。
購物清單名稱、數量、圖片、預估花費(納入統計)。

以 ＋ 新增清單 建立、＋ 新增項目、－ 刪除。

8. 日程設定

點右下角 🗓️ 日程設定 開啟,可調整出發日期、總天數、各天順序。

8.1 核心觀念:日期綁「位置」

每天日期由「排第幾天」自動算出,不綁在該天身上。調整順序 / 天數搬動的是「該天內容」,第 1 天永遠是出發日。例:把第 3 天移到第 1 天 = 原第 3 天的安排改到出發日進行。

8.2 面板內容

  • 出發日期(三下拉)、總天數(1–60)。
  • 各天列:第 N 天・日期(星期)・起點 → 終點路線摘要(便於辨識相似的天)。
  • 底部顯示變更摘要,將刪除且含內容者以紅字警示。

8.3 調整順序(即時預覽)

▲▼ 或拖曳 ⠿,主畫面即時反映。逐日模式下會持續跟著你正在移動的那天。

8.4 增減天數與預覽

減少時超出的天先在刪除線下預覽(不立即刪),按套用才刪;含內容會再確認;套用前可 ▲▼ / 拖曳把要保留的天移到線上搶救。增加時預覽新增的空白天。

8.5 套用與取消

動作結果
✓ 套用確認變更並生效。
取消 / ✕ / 點面板外放棄變更,還原到開啟前。

9. 總覽與匯出

9.1 行程總覽

點 📋 行程總覽 彈出完整預覽(與 PDF 一致),上方有匯出鈕。

9.2 匯出 PDF

  1. 點 📄 匯出 PDF。要把 PDF 附件的內容印出來,一定要用這個鈕;直接按 Ctrl+P 時 PDF 附件只會以末頁清單呈現。
  2. 目的地選「另存為 PDF」。
  3. 檔名自動帶入標題,確認版面後儲存。

順序:標題 → 各日 → 一頁式費用總覽 → 清單 → 圖片附件(每張一頁)→ PDF 附件的逐頁內容(每頁一頁)→ 無法轉換的 PDF 附件清單。列印一律淺色。

9.3 匯出 Excel

點 📊 匯出 Excel 產生 .xlsx,分頁:行程表 / 餐食 / 住宿 / 花費總覽 + 各清單;圖片內嵌、Email / 網站為超連結。

PDF / Excel 無法讀回編輯,要再編請存 JSON。

10. 儲存與讀取

JSON 是唯一可完整還原編輯的格式。

按鈕行為
📂 讀取行程開啟 .json 續編(舊版自動相容)。
💾 儲存行程若此行程有來源檔(經讀取或另存過)→ 直接寫回原檔;否則等同另存新檔。
📁 另存新檔選擇位置存成新檔,之後「儲存」會改寫入這個新檔。
原檔回存與資料夾記憶(Chrome / Edge):讀取或另存後會記住檔案與所在資料夾;下次讀檔/存檔的選擇器會從上次資料夾開始,關閉瀏覽器重開仍有效。首次寫回原檔時瀏覽器會詢問一次寫入權限,允許即可。
  • 繼續上次行程:啟動預設回首頁;若曾開啟過檔案,首頁會出現「↻ 繼續上次行程」,點了會直接讀取「最後開啟的那個實體檔」的目前內容(不是讀瀏覽器暫存)。因此該檔已刪除 / 移動則會報錯,不會載回舊資料。
  • 自動暫存:編輯過程存於瀏覽器(localStorage),只保留最後一次、與該瀏覽器綁定(此為安全網,「繼續」不使用它)。
務必自行另存 JSON 備份——清除瀏覽器資料 / 換機 / 換瀏覽器都會使自動暫存與路徑記憶遺失。
關於權限提示:讀寫離線檔通常直接進行、不跳提示;但關閉瀏覽器重開後第一次存取檔案時,瀏覽器(Edge/Chrome)會原生要求確認一次(「是否允許檢視/編輯檔案」),此為瀏覽器資安機制,程式無法移除。
關於資料位置:工具全程離線,不上傳、不複製到其他位置;僅在本機瀏覽器保存自動暫存(localStorage)與檔案參照(IndexedDB)。
file://(雙擊)下少數瀏覽器版本不支援原檔回存 / 資料夾記憶而退回下載;改以 localhost 開啟即穩定。Firefox / Safari 不支援,一律走下載。

12. 提示與常見問題

問題說明

ボタン動作
📂 読み込み.json を開いて続行(旧版も自動互換)。
💾 保存この旅程に元ファイルがある(読み込み/名前を付けて保存済み)→ 元ファイルに上書き;無ければ「名前を付けて保存」と同じ。
📁 名前を付けて保存場所を選んで新規保存。以後の「保存」はこの新ファイルへ。
元ファイル上書きとフォルダ記憶(Chrome / Edge):読み込み/保存したファイルとフォルダを記憶し、次回のダイアログは前回のフォルダから開始。ブラウザを閉じても有効。初回の上書き時に書き込み許可を一度尋ねられます。
  • 前回の続き:起動時は既定でホーム;過去にファイルを開いていればホームに「↻ 前回の続き」が表示され、押すと「最後に開いた実ファイル」の現在の内容を直接読み込みます(ブラウザの一時保存ではありません)。そのためファイルが削除・移動されているとエラーになり、古いデータは復元しません。
  • 自動保存:編集中はブラウザ(localStorage)に最後の 1 回のみ、端末 / ブラウザに紐づく(安全網であり「前回の続き」では使用しません)。
必ず JSON でバックアップを——ブラウザデータ削除 / 機種変更で自動保存とパス記憶は失われます。
権限の確認について:オフラインのファイルは通常そのまま読み書きでき確認は出ませんが、ブラウザを閉じて再起動した後の初回アクセス時に、ブラウザ(Edge/Chrome)が一度だけ確認します(「ファイルの表示/編集を許可しますか」)。これはブラウザのセキュリティ機構で、プログラムからは消せません。
データの場所:本ツールは常にオフラインで、アップロードや別の場所へのコピーはしません;端末のブラウザに自動保存(localStorage)とファイル参照(IndexedDB)を保持するのみです。
file://(ダブルクリック)では一部のブラウザ版で上書き / フォルダ記憶が使えずダウンロードに切替わります。localhost で開くと安定します。Firefox / Safari は非対応でダウンロードになります。

🧭 Business Trip Itinerary Planner — User Manual

Single self-contained HTML · Works offline · No install · 繁中 / 日本語 / English

This tool is a single HTML file (index.html). Double-click to open it offline in any browser. No install, no network, and nothing is uploaded — all your data stays on your own computer.

1. Overview & Features

Plan multi-day business trips / travel. One itinerary records each day's route, transport (multi-leg transfers), meals, hotels, attachments (tickets / booking confirmations), and a per-currency cost summary, plus packing and shopping lists. Export to PDF or Excel.

Design principles

  • Self-contained & offline: everything in one HTML file; works without internet. The only bundled third-party component is PDF.js, used to rasterise PDF attachments for printing (embedded in this file, local-only, never accesses the network).
  • Data stays local: nothing uploaded; edits auto-saved in the browser.
  • Trilingual UI: 繁中 / 日本語 / English. Your entered content is never translated.

The three file roles (important)

FormatRoleRe-editable
JSONThe only save / load format; contains everything incl. embedded attachments✔ Fully restorable
PDFOutput for sharing / printing (via browser print)✘ Output only
ExcelOutput for spreadsheets✘ Output only
Rule of thumb: to keep editing later, save JSON; to share / print / archive, export PDF or Excel.

🗺️ Map (online edition only): the 🗺️ next to "Activity N" expands a Google map inside the card showing the route from the departure place to the arrival place (if the arrival place is empty it falls back to Destination; if only one is filled it shows that single place). Below the map, "Open in Google Maps ↗" opens the full map in a new tab.
· One full route map per day: each day header has a 🗺️ Day route button on the right that chains every activity of that day into a single multi-stop route. If the next activity departs from where the previous one arrived, that place counts once (A→B, B→C gives A→B→C); if it departs from somewhere else, both places are kept (A→B, B'→C gives A→B→B'→C).
· Two limits apply: transit does not support waypoints (with stops in between the route falls back to driving — use a single activity's map for transit), and there is a maximum of 9 waypoints (extra middle stops are dropped and the count is stated below the map; the start and end are always kept).
· Above the map are four travel modes: 🚗 Drive / 🚆 Transit / 🚶 Walk / 🚲 Bike. Picking one reloads the map in that mode and remembers your choice for the next activity you expand.
· For alternative routes (e.g. Ginza line vs JR), use "Open in Google Maps ↗" — it carries your selected mode over, and the Google Maps page lists each route with its duration and transfers. The in-card map only draws a single route; that is a limitation of embedded maps.
· Only one map is open at a time — expanding another collapses the previous one; press 🗺️ again to collapse.
· After editing the place fields, collapse and expand again to reload with the new places.
· The map requires an internet connection (loaded from Google the moment you expand it) and never appears in PDF / Excel output. If outbound connections are not allowed in your environment, use the offline edition in offline/ — it has no map feature and contains no networking code at all.

10. Save & Load

JSON is the only fully restorable format.

ButtonBehavior
📂 LoadOpen a .json to continue (older files auto-migrate).
💾 SaveIf this itinerary has a source file (loaded or saved-as) → writes back to the original; otherwise same as Save As.
📁 Save AsPick a location for a new file; later “Save” writes to this new file.
Overwrite original & folder memory (Chrome / Edge): the file and its folder are remembered, so the next load/save dialog starts in the last folder — persists across browser restarts. The first overwrite asks for write permission once.
  • Resume last: startup returns to Home by default; if you've opened a file before, Home shows “↻ Resume Last” — it reads the current content of the last opened file directly (not the browser cache). So if that file was deleted / moved it errors and won't bring back stale data.
  • Auto-save: kept in the browser (localStorage), last state only, tied to that browser (a safety net; not used by Resume Last).
Always keep your own JSON backups — clearing browser data / switching device or browser loses the auto-save and the remembered path.
About the permission prompt: offline files usually read/write directly with no prompt, but the first file access after restarting the browser triggers a one-time native confirmation from the browser (Edge/Chrome) — a security mechanism that the app cannot remove. Data location: the tool is fully offline; nothing is uploaded or copied elsewhere — only the auto-save (localStorage) and a file reference (IndexedDB) are kept in your local browser. file:// (double-click): some browser versions fall back to download (no overwrite / folder memory); open via localhost for reliability. Firefox / Safari don't support this and always download.
